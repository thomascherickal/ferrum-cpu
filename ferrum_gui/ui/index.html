Prepare — clean, deduplicate and split a dataset

Reads text files or whole folders straight from disk (a big corpus never goes through this window), cleans every document, and writes train.txt, val.txt, test.txt and a manifest.json that records what was done. It runs the same code as train_transformer prepare, so the same options give the same files.

Train a transformer SLM

Tokenize a large corpus first (optional)

For text too big to hold in memory: turn it into a token file once, then put that file in the Corpus field above. Training streams it from disk, so RAM does not grow with the corpus. It uses the Tokenizer file field above, which must already exist (a first training run with that field filled in creates it), and gives the same model as training on the text.

GGUF — import & run a Llama/Qwen checkpoint

      
Load an external .gguf model (F32/F16/Q8_0/Q8_1/Q4_0/Q4_1/Q4_K/Q5_K/Q6_K)
        and generate from it. CPU-only: a 1B model decodes at only a few tokens/sec and a
        real prompt takes tens of seconds to ingest. Prefer int8 for speed,
        int4 for memory. Quantized import is lossy; f32 avoids it.

      

        
        
        
      

      

      
      

        
        
        
        
        
        
        
      

      
      
      

        
        
      

      
      
      
      

        
        
        
      

      

    


    
    

      
Fine-tune — adapt an imported GGUF to your corpus

      
AdamW fine-tunes a Llama/Qwen .gguf on your own text (full-precision f32 masters),
        then writes a .flck checkpoint. Run it back on the GGUF tab via the
        “Fine-tune checkpoint” field. CPU-only: keep the model small — training needs roughly
        4× the f32 weight size in RAM (weights + gradient + Adam moments).

      

        
        
      

      

        
        
      

      

        
        
      

      

        
        
        
        
        
        
        
        
        
        
      

      

        
        
      

      
      
      
      

        
        
        

        
      

      
      

    


    
    

      
Export — write a model back to GGUF

      
Serializes a Llama/Qwen .gguf — optionally with a
        fine-tune checkpoint applied — to a new GGUF that runs in llama.cpp, ollama,
        or LM Studio. f16/f32 are lossless (f32 masters); re-quantizing an
        already-quantized file is lossy. Norms and biases stay f32; a matrix whose row
        length is not block-aligned for the chosen type falls back to f16 (the summary
        below shows exactly what was written).

Serve — an HTTP server for one model

      
Starts the same server as the ferrum-serve command inside this
        window, so other programs (an evaluation harness, a script, curl) can score
        text and generate with a Ferrum model over HTTP. One model at a time. It listens on this
        machine only unless you change the host, and then it needs a bearer token. Nothing is sent
        anywhere else.

Capable — what can this machine run?

      
Runs a quick (~1–2 s) micro-benchmark of memory bandwidth and
        matmul throughput on this CPU, then estimates the parameter range of an
        SLM this machine can load, train (< 24 h),
        fine-tune (< 24 h), and run (≥ 3 tok/s),
        plus a 24 h eval bound. Estimates are upper bounds — real models vary with
        architecture and context length.
